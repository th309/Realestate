How should 15 cards be organized?

Your current command center has 6 cards on one page. With 15, we need structure.

A

Tabbed Sections

Group cards into tabs: Operations (API, Cache, Alerts, Pipelines, Data Feeds), Data & Scores (Score Health, Coverage, Quality, ML Ops, Computation), Business (Users, Revenue, Feature Usage, Tier Distribution, Feedback). Each tab shows 5 cards in a clean grid. Top-level health banner stays visible across all tabs.

Pros

  • Clean, focused view per domain
  • Easy to add more cards later
  • Fast — only renders one tab's data

Cons

  • Can't see cross-domain at a glance
  • Requires clicking between tabs
B

Grafana-Style: Priority Row + Scrollable Sections

Top row: 4-5 hero stat cards (API health, active alerts, total users, data freshness, MRR) — always visible, compact. Below: collapsible sections (Operations, Data & Scores, Business) each containing their detailed cards with charts. Like Grafana's row-based layout.

Pros

  • Key metrics always visible at top
  • Full picture on one page
  • Collapse sections you don't need right now

Cons

  • Long scrollable page when all expanded
  • More data loaded at once
C

Hybrid: Hero Stats + Tabs

Combines A and B. Top row: 5 hero stat cards with sparklines (always visible). Below: tabbed detail sections for the full cards. Best of both — instant glance at health, then drill into any domain.

Pros

  • Instant health overview without scrolling
  • Detailed view organized by tabs
  • Scales well as you add more cards

Cons

  • Slightly more complex layout
  • Hero stats duplicate some tab content
