# Monorepo Cleanup — Phase 0: Safety Net + Test Triage

**Date:** 2026-07-01
**Scope:** Report only. Zero code changes made during this phase.
**Method:** 4 recon agents (backend test run, frontend test run, critical-path map, build baseline) followed by 46 individual test-file classifications + 4 directory pattern-scans, all dispatched as parallel background agents.

---

## 0. Headline findings (read this first)

1. **CI never runs the frontend test suite, anywhere.** `.github/workflows/ci.yml` has a `test-backend` job but no `test-frontend` job, and no other workflow file references vitest. The 234-file, 1053-test frontend suite (`packages/frontend`) is currently a local-developer-discipline safety net only — completely unenforced by CI. This changes the risk calculus for every later phase: a frontend regression from this cleanup would not be caught by CI, only by whoever remembers to run `npm run test:unit -w web` by hand.
2. **Zero tests anywhere in the repo currently verify PropertyIQ Score's correct label output.** Three separate test files (`ScoreDisplay-utilities.test.ts`, `ListingPresentation.realrender.test.tsx`, `MarketComparisonView.test.tsx`) all assert the _retired_ quality-word labels (GOOD/FAIR/etc.) that CLAUDE.md §9 explicitly forbids. A repo-wide grep for the current momentum labels (VERY STRONG, FIRMING, etc.) in test files returned zero matches. The real `getScoreLabel()` implementation is correct — the tests are all stale in the same direction.
3. **Two "integration" test files on the PropertyIQ Score critical path are almost entirely fake.** `scoring-pipeline.spec.ts` (~28 of ~30 tests are literal `expect(true).toBe(true)` placeholders) and `monitoring.spec.ts` (tests a `ScoreAnomalyService` that doesn't exist anywhere in production) both look like real coverage and aren't. This is the exact "Misleading — dangerous" failure mode called out in the cleanup spec.
4. **Fix & Flip Upgrade Path has zero test coverage at every layer** (analyzer-core math, backend controller, frontend panel/option components) despite being a fully shipped feature, and **`grade-flip.controller.spec.ts` calls the wrong controller method**, so the real `/grade-flip` HTTP endpoint also has no real coverage. Fix & Flip is the weakest-protected of the three grading strategies.
5. **`/graphs` has zero test files anywhere** — 8 chart-data hooks (not the 5 the original spec named — please confirm the intended scope), zero coverage.
6. Both apps **build clean** on `develop` as-is. One real (not cosmetic) build finding: a webpack case-sensitivity conflict that's silently tolerated on Windows but could break on Railway's Linux build.
7. One likely **real product regression**, not just a stale test: `run-actions.service.spec.ts` shows the content-pipeline state machine silently dropped a "skip re-verification if the script is untouched since a failed gate" grace period. Needs a human call, not a mechanical test fix.

These 54 files' actual pass/fail status is currently unknown and unverifiable without a manual, env-configured run.
